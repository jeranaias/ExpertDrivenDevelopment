# Expert-Driven Development

## Overview
A static GitHub Pages site providing open-source AI-assisted development training for DoW personnel. The site contains training courses, an SOP, an interactive toolkit, tools, and downloadable templates.

## Project Type
Static HTML/CSS/JS site (originally hosted via GitHub Pages from the `docs/` directory).

## Project Structure
- `docs/` — site root (HTML pages, CSS, JS, PDFs, course materials)
- `docs/facilitator/` — one-page printable Facilitator Packs (one per week) at `week-{1..6}-<slug>.html`. Shared landscape print stylesheet at `docs/facilitator/css/pack.css` (Letter landscape, B&W safe via overrides in `@media print`; a trailing `@media screen`-only block styles the PDF download UI without touching print output). Each pack mirrors the EDD palette via the same scarlet/gold/warm-gray tokens used in the decks. Landing page at `docs/facilitator/index.html`. Cross-linked from `docs/decks/index.html` (per-card "Facilitator Pack" CTA + footer link to the index) and from each `docs/courses/<slug>.html` instructor page (prominent button row in the page header alongside the "Open the Slide Deck" primary button — see deck-discoverability note below).
  - **Browser-print one-pager guarantee.** The shipped `pack.css` `@media print` block bakes in a tighten-pass (line-height + padding + gap clamps; `overflow:hidden` on `.pk-box`; `1fr/1fr` row clamp on `.pk-body`; `.pack-page` width 10.36in × height 7.63in — the safe Letter+A4 intersection) so a user pressing Ctrl+P from any browser gets exactly one landscape page on Letter or A4. The clamps are scoped to `@media print` only — on-screen presentation is unchanged. Each pack and handout page also carries a screen-only "leave Margins at Default" tip (`.pack-intro__tip` / `.handout-intro__tip`, hidden in print via the parent intro's `display:none`) because a "Custom" or "Minimum" margin setting in the print dialog shrinks the printable area below what the layout assumes.
  - `docs/facilitator/pdf/week-{1..6}-<slug>.pdf` — pre-rendered Letter-landscape one-page PDFs of each pack, surfaced as "Download PDF" buttons on every pack page and listed on the Facilitator landing page (with a "Regenerating the PDFs" `<details>` callout).
  - **Regenerating the PDFs:** with the "Start application" workflow running, run `npm run build:facilitator-pdfs` from the project root. The script (`scripts/build-facilitator-pdfs.js`) launches headless Chromium via `puppeteer-core`, loads each pack from `http://localhost:5000/facilitator/`, and writes Letter-landscape PDFs to `docs/facilitator/pdf/`. The script no longer injects a per-render tighten stylesheet — it relies on the same `@media print` rules now baked into the shipped `pack.css`, so the PDF output and the browser-print preview stay in lockstep. System deps: `chromium` (Nix) or `google-chrome` (Ubuntu CI); recommended: `noto-fonts` (Nix) or `fonts-liberation` (Ubuntu) — the script auto-detects either family in `/nix/store` *or* the standard `/usr/share/fonts/truetype/{liberation,noto}` paths and wires up a temporary fontconfig file so headless Chromium aliases the pack's font stack to Liberation Sans (preferred) or Noto Sans. npm dep: `puppeteer-core` (declared in `package.json`).
  - **Auto-rebuild on every push:** `.github/workflows/rebuild-facilitator-pdfs.yml` re-runs the build on every push to `main` that touches `docs/facilitator/week-*.html`, `docs/facilitator/css/pack.css`, or the build script itself, then commits the refreshed PDFs back to `main`. The workflow is also runnable manually (`workflow_dispatch`). HTML is the source of truth; never hand-edit a PDF — edit the pack HTML and let CI regenerate, or run `npm run build:facilitator-pdfs` locally and commit the result. The CI commit uses the default `GITHUB_TOKEN`, which does not retrigger workflows, so there is no rebuild loop.
- `docs/handouts/` — one-page printable Student Handouts (one per week) at `week-{1..6}-<slug>.html`. Shared landscape print stylesheet at `docs/handouts/css/handout.css` mirrors the print contract of `docs/facilitator/css/pack.css` (A4/Letter landscape, B&W safe via overrides in `@media print`, including the same browser-print tighten-pass under the parallel `.hd-*` namespace) under a parallel `.hd-*` namespace and `.handout-page` wrapper. Student-facing only — the five-box body grid is "Bring with you / Key terms / Exercises in class / What you'll be able to do / Homework," with no facilitator hand-off cues or recovery scripts. Landing page at `docs/handouts/index.html`. Linked from each `docs/courses/<slug>.html` page as an additional secondary button ("Open the Student Handout") plus a small "Download Handout PDF" outline button (`btn btn--secondary btn--sm` with `download`, pointing at `../handouts/pdf/week-N-<slug>.pdf`) in the deck-discoverability action row described below.
  - `docs/handouts/pdf/week-{1..6}-<slug>.pdf` — pre-rendered Letter-landscape one-page PDFs of each handout, surfaced as a "Download PDF" button on every handout page (inside the screen-only `.handout-intro` block, hidden in print) and on each card on the handouts landing page (alongside an "Open handout" link), plus a consolidated "Download all six handout PDFs" callout list with a "Regenerating the PDFs" `<details>` block. Aimed at Marines on shared / kiosk laptops where the print dialog is locked down.
  - **Regenerating the PDFs:** with the "Start application" workflow running, run `npm run build:handout-pdfs` from the project root. The script (`scripts/build-handout-pdfs.js`) is a near-verbatim sibling of `scripts/build-facilitator-pdfs.js` — same headless-Chromium / `puppeteer-core` setup, same Liberation-Sans / Noto-Sans fontconfig fallback, same Letter-landscape + 0.32in margins, plus a per-output one-page assertion (`pdfinfo` if present, otherwise a `/Type /Page` byte scan). Output dir: `docs/handouts/pdf/`. Whoever edits a handout's HTML must re-run the script before committing so the PDF stays in lockstep with the on-page content.
  - **Browser-print verification.** All 12 pages (6 facilitator packs + 6 handouts) were verified to render as exactly one page via headless Chromium PDF in both Letter and A4 landscape with 0.32in margins. Visual spot-check on the densest pages (Weeks 5 and 6, both packs and handouts) confirmed no clipping and no orphaned footer line. Re-verifiable on demand via `npm run verify:facilitator-a4` (script: `scripts/verify-facilitator-a4.js`) — renders every pack to both A4 and Letter landscape PDFs with the production margins and asserts each output is exactly one page (`pdfinfo` from poppler-utils, already in the Nix runtime path). Outputs land in `.local/a4-verify/` (gitignored) for visual spot-checking. Edge prints from the same Chromium engine as Chrome, so a green run here covers Edge as well.

Shared CSS additions: `.page-header__actions` (flex row with wrap + gap) and `display:flex;flex-wrap:wrap;gap` on `.card__footer` in `docs/css/style.css`.

All six decks now share a single canonical `css/deck.css` and `js/deck.js`. Each deck declares its own `<body class>` (`deck-body`, `w2-deck`, `w3-deck`, `w4-deck`, `w5-deck`, `w6-deck`) so per-week styles live side-by-side without conflict. Features keyboard/click nav, hash deep-linking, speaker-notes pane (`N`), fullscreen (`F`), print/PDF export (`P`, one slide + speaker notes per 1920×1580 page, uniform across all six decks), an instructor-style multi-up student-handout print mode triggered by `?handout=1/2/4` (rendered via `body.is-handout` rules), and 1920×1080 auto-scaling for Weeks 2/4 (Week 1 is viewport-relative; Week 3 sizes its `.deck` to `100svw/100svh`; Weeks 5/6 self-scale via CSS `aspect-ratio`).

## Replit Setup
- **Workflow:** "Start application" runs `python3 serve.py` on port 5000.
- `serve.py` serves the `docs/` directory on `0.0.0.0:5000` and disables HTTP caching for development so changes appear immediately in the proxied preview.
- **Deployment:** Configured as `static` with `publicDir = "docs"`.

## Notes
- No backend, database, or build step. Pure static files.
- The only request that 404s is `/favicon.ico`, which the upstream repo does not include.

## Weekly Decks (Microsoft Teams, 16:9)
Self-contained HTML slide decks that mirror the EDD visual identity (USMC Scarlet `#CC0000`, Gold `#F5D130`, warm gray, near-black) inline. Each deck supports keyboard nav (← →, Space, Home/End), `N` toggles a speaker-notes overlay, `F` fullscreen, `P` print (one slide per page), `?` for help. Speaker notes are layered with parallel `[BRIEFING]` / `[JOINT]` / `[TRANSITION]` tracks so the same deck supports both the tight 30-min briefing and the extended joint session.
